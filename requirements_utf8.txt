Методические указания к практическому занятию №1
Git, GitHub, Pull Request и GitHub Pages
1. Цель работы
Цель практического занятия — подготовить рабочее окружение для выполнения практических и контрольных работ по дисциплине, освоить базовый цикл работы с Git, создать учебный frontend-проект, опубликовать его на GitHub, выполнить доработку через отдельную ветку и Pull Request, а также настроить публикацию проекта с помощью GitHub Pages.
В результате выполнения работы студент должен:
создать локальный Git-репозиторий;
создать базовую структуру учебного frontend-проекта;
оформить файлы README.md и .gitignore;
выполнить первые осмысленные коммиты;
создать удалённый репозиторий на GitHub;
связать локальный репозиторий с GitHub;
отправить основную ветку проекта в GitHub;
создать отдельную ветку для доработки;
выполнить Pull Request через веб-интерфейс GitHub;
выполнить слияние изменений в основную ветку;
настроить публикацию проекта на GitHub Pages;
добавить ссылку на опубликованный сайт в README.md.
2. Связь с контрольной работой
Практическое занятие связано с контрольной работой №1 по теме:
«HTML и CSS: разработка многостраничного сайта».
На следующих практических занятиях созданный репозиторий будет использоваться как основа для разработки многостраничного HTML/CSS-сайта интернет-магазина или каталога услуг.
На данном занятии создаётся техническая база проекта:
локальный репозиторий;
удалённый репозиторий GitHub;
базовая HTML-страница;
файл стилей;
README.md;
.gitignore;
история коммитов;
ветка для доработки;
Pull Request;
публикация через GitHub Pages.
Если практические занятия проводятся парами в один день, результат данной работы используется сразу на следующем практическом занятии по теме HTML/CSS. Поэтому к концу занятия проект должен быть сохранён в GitHub и доступен по ссылке.
3. Краткая теория
3.1. Что такое Git
Git — это система контроля версий, которая позволяет отслеживать изменения в файлах проекта, сохранять историю разработки и возвращаться к предыдущим состояниям проекта.
Git особенно важен в веб-разработке, потому что позволяет:
фиксировать этапы разработки;
видеть, какие изменения были внесены;
работать с несколькими версиями проекта;
выполнять командную разработку через ветки и Pull Request;
хранить проект в удалённом репозитории.
3.2. Что такое репозиторий
Репозиторий — это папка проекта, в которой Git отслеживает изменения файлов.
Репозиторий бывает:
локальный — находится на компьютере разработчика;
удалённый — находится на сервере, например на GitHub.
Упрощённо:
Компьютер студента → GitHub
локальный проект     удалённый репозиторий
3.3. Что такое коммит
Коммит — это зафиксированное состояние проекта в определённый момент времени.
Коммит должен быть осмысленным. Не рекомендуется делать один большой коммит на всю работу. Лучше фиксировать изменения по этапам:
создана структура проекта;
добавлен файл index.html;
подключён файл стилей;
оформлен README.md;
добавлена ссылка на опубликованный сайт.
3.4. Что такое README.md
README.md — это файл с описанием проекта. Он должен объяснять, что находится в репозитории, как устроен проект и как его проверить.
Минимально в README.md должны быть:
название проекта;
краткое описание;
структура проекта;
используемые технологии;
ссылка на опубликованную версию сайта;
ФИО и группа студента.
3.5. Что такое .gitignore
.gitignore — это файл, в котором указываются файлы и папки, которые не нужно добавлять в репозиторий.
Пример:
.DS_Store
Thumbs.db
.vscode/
node_modules/
dist/
build/
*.log
.env
3.6. Что такое ветка
Ветка — это отдельная линия разработки.
Основная ветка обычно называется:
main
Ветка main должна хранить стабильную версию проекта.
Для отдельной доработки создаётся отдельная ветка, например:
feature/start-page
Это означает: «ветка для доработки стартовой страницы».
3.7. Что такое Pull Request
Pull Request — это запрос на добавление изменений из одной ветки в другую.
В рамках данной практической работы Pull Request будет означать:
Добавить изменения из ветки feature/start-page в ветку main.
Pull Request создаётся не в терминале, а в веб-интерфейсе GitHub.
В терминале студент создаёт ветку, делает коммит и отправляет ветку в GitHub. Затем в браузере на GitHub создаётся Pull Request.
3.8. Что такое Merge
Merge — это слияние изменений.
После проверки Pull Request студент нажимает кнопку Merge pull request. После этого изменения из ветки feature/start-page попадают в ветку main.
3.9. Что такое GitHub Pages
GitHub Pages — это сервис GitHub для публикации статических сайтов.
Он позволяет открыть HTML/CSS-проект как обычный сайт в браузере.
Пример ссылки:
https://username.github.io/kr1-html-css-shop/
GitHub Pages — это не Pull Request.
Разница между действиями:
Действие
Что означает
git push
отправить код в GitHub
Pull Request
предложить изменения из одной ветки в другую
Merge
объединить изменения
GitHub Pages
опубликовать сайт в интернете
4. Исходные требования
Перед выполнением работы необходимо:
Иметь установленный браузер.
Иметь установленный Visual Studio Code.
Иметь установленный Git.
Иметь учётную запись GitHub.
На учебных компьютерах установка программ и изменение системных настроек могут быть недоступны из-за политики безопасности. В таком случае студент выполняет только проверку доступности Git и VS Code. Если нужные программы не установлены, необходимо сообщить преподавателю.
5. Проверка установки Git
Откройте терминал и выполните команду:
git --version
Если Git установлен корректно, в терминале появится номер версии, например:
git version 2.45.0
Если команда не распознана, необходимо установить Git или обратиться к преподавателю, если работа выполняется на учебном компьютере.
Установка Git на личном компьютере
Для Windows Git можно скачать с официального сайта:
https://git-scm.com/
Для macOS при наличии Homebrew можно выполнить:
brew install git
Для Ubuntu/Debian:
sudo apt update
sudo apt install git
6. Настройка имени пользователя и e-mail
После установки Git необходимо один раз указать имя пользователя и e-mail.
git config --global user.name "Ваше Имя"
git config --global user.email "your-email@example.com"
Проверить настройки можно командой:
git config --global --list
На учебном компьютере глобальные настройки могут сохраняться для текущего пользователя системы. Если компьютер используется разными студентами, не оставляйте личные данные без необходимости и следуйте правилам безопасного завершения работы из приложения А.
7. Общая схема выполнения работы
На практике нужно выполнить следующий маршрут:
1. Создать локальный проект.
2. Инициализировать Git-репозиторий.
3. Создать базовые файлы проекта.
4. Выполнить первые коммиты.
5. Создать репозиторий на GitHub.
6. Связать локальный проект с GitHub.
7. Отправить основную ветку main в GitHub.
8. Создать ветку feature/start-page.
9. Внести небольшое изменение в index.html и style.css.
10. Сделать коммит в отдельной ветке.
11. Отправить ветку в GitHub.
12. Создать Pull Request в браузере.
13. Выполнить Merge Pull Request.
14. Настроить GitHub Pages.
15. Добавить ссылку на сайт в README.md.
8. Задание
Необходимо создать учебный frontend-проект, оформить его как Git-репозиторий, опубликовать на GitHub, выполнить доработку через ветку и Pull Request, а затем настроить публикацию проекта через GitHub Pages.
Рабочее название проекта:
kr1-html-css-shop
Проект представляет собой будущий многостраничный сайт интернет-магазина или каталога услуг.
9. Порядок выполнения работы
Если выполняете на своем компьютере и у вас не установлен VScode – воспользуйтесь инструкцией - установка и настройка Visual Studio Code: https://habr.com/ru/articles/490754/. 
Так же дополнительный материал по Git доступен по ссылкам ниже: 
Git. Часть 1: https://habr.com/ru/articles/541258/
Git. Часть 2: https://habr.com/ru/articles/542616/
Этап 1. Создание локального проекта
Создайте на компьютере папку:
kr1-html-css-shop
Откройте эту папку в Visual Studio Code.
В Visual Studio Code откройте терминал:
Terminal → New Terminal
Убедитесь, что терминал открыт в папке проекта.
Этап 2. Инициализация Git-репозитория
Выполните команду:
git init
После этого в папке проекта будет создан скрытый каталог .git.
Проверьте состояние репозитория:
git status
Этап 3. Создание базовой структуры проекта
Создайте следующую структуру:
kr1-html-css-shop/
├── index.html
├── css/
│   └── style.css
├── images/
├── README.md
└── .gitignore
На данном занятии достаточно создать только стартовую страницу index.html. Остальные страницы будут добавлены на следующих практических занятиях.
Этап 4. Заполнение файла .gitignore
Добавьте в .gitignore следующий текст:
# Системные файлы
.DS_Store
Thumbs.db
# Настройки редактора
.vscode/
# Логи
*.log
# Временные файлы
*.tmp
*.temp
# Переменные окружения
.env
.env.*
Этап 5. Создание базового HTML-файла
В файле index.html разместите базовую структуру HTML-документа:
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Каталог товаров</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <header>
    <h1>Учебный интернет-магазин</h1>
  </header>
  <main>
    <section>
      <h2>Главная страница проекта</h2>
      <p>
        Это стартовая страница учебного frontend-проекта.
        В дальнейшем здесь будет разработан многостраничный сайт
        интернет-магазина или каталога услуг.
      </p>
    </section>
  </main>
  <footer>
    <p>&copy; 2026 Учебный проект</p>
  </footer>
</body>
</html>
Этап 6. Добавление базовых стилей
В файле css/style.css разместите минимальные стили:
body {
  margin: 0;
  font-family: Arial, sans-serif;
  line-height: 1.5;
}
header,
main,
footer {
  padding: 20px;
}
header {
  background-color: #f2f2f2;
}
footer {
  background-color: #f2f2f2;
}
На данном этапе не требуется сложное оформление. Основная цель — проверить подключение CSS-файла.
Этап 7. Заполнение README.md
В файле README.md добавьте описание проекта:
# Учебный frontend-проект
## Описание
Проект выполняется в рамках дисциплины «Фронтенд и бэкенд разработка».
Тема проекта: многостраничный сайт интернет-магазина или каталога услуг.
## Структура проекта
- `index.html` — главная страница;
- `css/style.css` — файл стилей;
- `images/` — папка для изображений;
- `.gitignore` — список файлов, исключённых из Git;
- `README.md` — описание проекта.
## Используемые технологии
- HTML;
- CSS;
- Git;
- GitHub.
## Автор
ФИО: укажите свои данные  
Группа: укажите свою группу
Этап 8. Создание первых коммитов
Проверьте состояние репозитория:
git status
Добавьте файлы в индекс:
git add .
Создайте первый коммит:
git commit -m "feat: initialize frontend project structure"
Добавьте в README.md строку:
## Текущий статус
Создана базовая структура проекта.
Затем выполните:
git add README.md
git commit -m "docs: add project status to README"
Проверьте историю коммитов:
git log --oneline
В истории должно быть не менее двух коммитов.
Этап 9. Создание удалённого репозитория на GitHub
Откройте сайт GitHub и войдите в свой аккаунт.
Нажмите кнопку New repository.
Укажите имя репозитория:
kr1-html-css-shop
Выберите тип доступа:
Public
На данном этапе не добавляйте через интерфейс GitHub:
README.md;
.gitignore;
лицензию.
Эти файлы уже созданы локально в проекте.
Нажмите Create repository.
Этап 10. Связь локального проекта с GitHub
После создания репозитория GitHub покажет ссылку на него.
Она будет похожа на:
https://github.com/username/kr1-html-css-shop.git
Где username — имя вашего аккаунта GitHub.
В терминале, находясь в папке проекта, выполните команду:
git remote add origin https://github.com/username/kr1-html-css-shop.git
Замените username на имя своего аккаунта GitHub.
Проверьте связь с GitHub:
git remote -v
Должен появиться результат вида:
origin  https://github.com/username/kr1-html-css-shop.git (fetch)
origin  https://github.com/username/kr1-html-css-shop.git (push)
Этап 11. Отправка основной ветки в GitHub
Проверьте название основной ветки:
git branch
Если текущая ветка называется master, переименуйте её в main:
git branch -M main
Если она уже называется main, ничего менять не нужно.
Отправьте ветку main в GitHub:
git push -u origin main
После этого откройте страницу репозитория GitHub и обновите её.
В репозитории должны появиться файлы:
index.html
css/style.css
images/
README.md
.gitignore
Этап 12. Создание отдельной ветки для доработки
Теперь нужно сделать небольшое изменение не напрямую в main, а в отдельной ветке.
Создайте ветку:
git switch -c feature/start-page
Если команда git switch недоступна, используйте:
git checkout -b feature/start-page
Проверьте активную ветку:
git branch
Активная ветка будет отмечена символом *.
Пример:
* feature/start-page
  main
Этап 13. Доработка стартовой страницы
Откройте файл index.html.
Внутри тега <main> добавьте новую секцию:
<section>
  <h2>О проекте</h2>
  <p>
    В рамках данного проекта будет разработан многостраничный сайт
    интернет-магазина или каталога услуг. Проект будет постепенно
    расширяться на следующих практических занятиях.
  </p>
</section>
Откройте файл css/style.css и добавьте стили:
section {
  margin-bottom: 24px;
}
section h2 {
  margin-top: 0;
}
Сохраните файлы.
Этап 14. Коммит изменений в отдельной ветке
Проверьте изменённые файлы:
git status
Добавьте изменения в индекс:
git add index.html css/style.css
Создайте коммит:
git commit -m "feat: add project description section"
Проверьте историю:
git log --oneline
Этап 15. Отправка ветки в GitHub
Отправьте ветку feature/start-page в GitHub:
git push -u origin feature/start-page
После этого GitHub увидит новую ветку и предложит создать Pull Request.
Этап 16. Создание Pull Request в GitHub
Pull Request создаётся в браузере, на сайте GitHub.
Откройте страницу репозитория kr1-html-css-shop.
После отправки ветки GitHub обычно показывает кнопку:
Compare & pull request
Нажмите её.
Если кнопка не появилась, перейдите во вкладку Pull requests и нажмите New pull request.
Проверьте направление Pull Request:
feature/start-page → main
Это значит:
Добавить изменения из feature/start-page в main.
В поле заголовка напишите:
Add project description section
В поле описания напишите:
## Что сделано
- Добавлена секция «О проекте» на главную страницу.
- Добавлены базовые стили для секций.
## Как проверить
- Открыть `index.html` в браузере.
- Проверить, что секция «О проекте» отображается.
- Проверить, что CSS-файл подключён корректно.
Нажмите Create pull request.
Этап 17. Проверка и слияние Pull Request
После создания Pull Request откройте вкладку Files changed.
Проверьте:
акие файлы были изменены;
нет ли лишних файлов;
понятны ли изменения;
нет ли случайных файлов из операционной системы или редактора.
Если всё правильно, нажмите:
Merge pull request
Затем:
Confirm merge
После этого изменения попадут в ветку main.
Если GitHub предложит удалить ветку, можно нажать:
Delete branch
В учебном проекте это допустимо, потому что ветка уже была объединена с main.
Этап 18. Обновление локальной ветки main
После слияния изменений на GitHub нужно обновить локальную ветку main.
Переключитесь на main:
git switch main
Получите изменения из GitHub:
git pull origin main
Проверьте историю:
git log --oneline --graph
Теперь локальная ветка main должна содержать изменения, которые были объединены через Pull Request.
Этап 19. Настройка GitHub Pages
GitHub Pages настраивается в веб-интерфейсе GitHub.
На странице репозитория откройте:
Settings → Pages
В разделе Build and deployment выберите:
Deploy from a branch
В поле Branch выберите:
main
В поле папки выберите:
/(root)
Нажмите Save.
GitHub Pages может публиковать сайт не сразу. Подождите несколько минут.
После публикации появится ссылка вида:
https://username.github.io/kr1-html-css-shop/
Откройте её в браузере.
Этап 20. Добавление ссылки на опубликованный сайт в README.md
После настройки GitHub Pages нужно добавить ссылку на сайт в README.md.
Откройте файл README.md и добавьте раздел:
## Ссылка на опубликованный проект
GitHub Pages: https://username.github.io/kr1-html-css-shop/
Замените username на имя своего аккаунта GitHub.
Сделайте коммит в ветке main:
git add README.md

Приложение А. Работа с GitHub на учебном компьютере и безопасное завершение занятия
А.1. Общая рекомендация
Если практическая работа выполняется на учебном компьютере, необходимо учитывать ограничения политики безопасности аудитории. У студента может не быть прав администратора, доступа к системным настройкам, диспетчеру учётных данных, установке программ или изменению глобальных параметров операционной системы.
Поэтому на учебных компьютерах рекомендуется использовать наиболее простой и безопасный сценарий:
Работать через веб-интерфейс GitHub и HTTPS-ссылки.
Не сохранять пароль, токен или данные входа в браузере.
После занятия выйти из аккаунта GitHub.
Проверить, что в браузере не осталась открытая сессия.
При необходимости удалить локальную папку проекта, если это разрешено правилами аудитории.
SSH-ключи рекомендуется настраивать только на личном компьютере. На учебном компьютере SSH следует использовать только в том случае, если преподаватель отдельно разрешил этот вариант и объяснил порядок безопасного завершения работы.
А.2. Почему на учебном компьютере лучше использовать HTTPS
GitHub поддерживает несколько способов подключения удалённого репозитория. Для учебных занятий чаще всего достаточно HTTPS.
Пример HTTPS-ссылки:
https://github.com/username/repository-name.git
Пример SSH-ссылки:
git@github.com:username/repository-name.git
Для учебного компьютера предпочтительнее HTTPS, потому что он не требует создания SSH-ключа на машине, которой пользуются разные студенты.
А.3. Когда нужен SSH-ключ
SSH-ключ нужен для постоянной и удобной работы с GitHub без повторного ввода данных авторизации.
SSH удобно использовать:
на личном ноутбуке;
на домашнем компьютере;
на рабочем компьютере, который закреплён за конкретным пользователем;
при регулярной разработке и частом использовании git push / git pull.
На учебном компьютере SSH-ключ использовать нежелательно, потому что приватный ключ может остаться на машине после занятия.
А.4. Как создать SSH-ключ на личном компьютере
Этот раздел предназначен для студентов, которые выполняют практические работы на личном компьютере.
Откройте терминал и выполните команду:
ssh-keygen -t ed25519 -C "your-email@example.com"
Вместо your-email@example.com укажите e-mail, связанный с вашим аккаунтом GitHub.
Если система предложит путь для сохранения, можно нажать Enter, чтобы использовать стандартный путь:
~/.ssh/id_ed25519
После создания ключа вы получите два файла:
id_ed25519
id_ed25519.pub
Файл id_ed25519 — приватный ключ. Его нельзя никому передавать.
Файл id_ed25519.pub — публичный ключ. Его можно добавить в GitHub.
А.5. Как добавить SSH-ключ в GitHub
Скопируйте публичный ключ:
cat ~/.ssh/id_ed25519.pub
Затем:
Откройте GitHub.
Нажмите на аватар в правом верхнем углу.
Перейдите в Settings.
Откройте раздел SSH and GPG keys.
Нажмите New SSH key.
В поле Title укажите название компьютера, например:
Personal laptop
В поле Key вставьте публичный ключ.
Нажмите Add SSH key.
Проверить подключение можно командой:
ssh -T git@github.com
Если подключение настроено правильно, появится сообщение об успешной аутентификации.
А.6. Как безопасно завершить работу на учебном компьютере
После выполнения практической работы на учебном компьютере выполните следующие действия.
Шаг 1. Убедитесь, что работа сохранена
Проверьте, что все нужные изменения сохранены в репозитории GitHub.
Если вы работали через Git в терминале:

git log --oneline
Если изменения ещё не отправлены в GitHub, выполните коммит и отправку изменений.
Шаг 2. Выйдите из аккаунта GitHub в браузере
Откройте GitHub.
Нажмите на аватар в правом верхнем углу.
Нажмите Sign out.
Закройте вкладку GitHub.
После этого снова откройте GitHub и проверьте, что сайт не открывается под вашим аккаунтом.
Шаг 3. Не сохраняйте пароль в браузере
Если браузер предложил сохранить пароль, выберите отказ:
Never
Не сохранять
Если пароль уже был сохранён, а удалить его через настройки браузера нельзя из-за политики безопасности, сообщите преподавателю или администратору аудитории.
Шаг 4. Удалите временный SSH-ключ из GitHub, если он был добавлен
Если на занятии вы добавляли SSH-ключ в GitHub, удалите его из аккаунта:
GitHub → Settings.
SSH and GPG keys.
Найдите ключ, добавленный на занятии.
Нажмите Delete.
Подтвердите удаление.
Даже если файл ключа остался на учебном компьютере, после удаления публичного ключа из GitHub он больше не сможет использоваться для доступа к вашему аккаунту.
Шаг 5. Удалите локальную папку проекта, если это разрешено
Если правила аудитории разрешают удалять созданные пользователем файлы, удалите локальную папку проекта после отправки работы в GitHub.
Перед удалением проверьте, что работа действительно отправлена в удалённый репозиторий.
Шаг 6. Проверьте выход из аккаунта
Перед завершением занятия убедитесь:
GitHub не открыт под вашим аккаунтом;
браузер не предлагает войти автоматически;
вы не оставили открытые вкладки с личным кабинетом;
ссылка на репозиторий сохранена и передана преподавателю.

4. Краткая теория
4.1. Что такое HTML
HTML — это язык гипертекстовой разметки, который используется для описания структуры веб-страницы.
HTML отвечает за смысловую структуру страницы:
где находится шапка сайта;
где расположено меню;
где основное содержимое;
где находится карточка товара или информационный блок;
где расположен подвал сайта.
HTML не отвечает за внешний вид страницы. За оформление отвечает CSS.
4.2. Базовая структура HTML-документа
Каждая HTML-страница должна иметь базовую структуру:
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Название страницы</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
</body>
</html>
Назначение основных элементов:
Элемент
Назначение
<!DOCTYPE html>
сообщает браузеру, что используется современный HTML
<html lang="ru">
задаёт язык страницы
<head>
содержит служебную информацию о странице
<meta charset="UTF-8">
задаёт кодировку страницы
<meta name="viewport">
помогает корректно отображать страницу на разных устройствах
<title>
задаёт название вкладки браузера
<link rel="stylesheet">
подключает внешний CSS-файл
<body>
содержит видимое содержимое страницы
4.3. Основные HTML-теги
Для построения страницы используются базовые HTML-теги.
Тег
Назначение
h1–h6
заголовки разных уровней
p
абзац текста
a
ссылка
img
изображение
ul, ol, li
списки
div
универсальный блочный контейнер
span
универсальный строчный контейнер
На данном занятии рекомендуется отдавать приоритет семантическим тегам, а не строить всю страницу только на div.
4.4. Семантические элементы HTML
Семантические элементы помогают описать смысл частей страницы.
Тег
Назначение
header
верхняя часть страницы или раздела
nav
навигационное меню
main
основное уникальное содержимое страницы
section
логический раздел страницы
article
самостоятельный смысловой блок
aside
дополнительный блок, связанный с основным содержимым
footer
нижняя часть страницы
Пример структуры:
<body>
  <header>
    <nav>
      <!-- Навигация -->
    </nav>
  </header>
  <main>
    <section>
      <!-- Основной раздел -->
    </section>
  </main>
  <footer>
    <!-- Подвал сайта -->
  </footer>
</body>
Важно: на странице должен быть только один основной тег main.
4.5. Что такое CSS
CSS — это язык стилей, который используется для описания внешнего вида HTML-документов.
CSS позволяет задавать:
цвета;
шрифты;
размеры;
отступы;
фон;
рамки;
выравнивание;
оформление ссылок, кнопок, секций и других элементов.
4.6. Подключение CSS к HTML
На практике используется внешний CSS-файл.
Внутри тега head необходимо подключить файл стилей:
<link rel="stylesheet" href="css/style.css">
Это означает, что браузер должен взять стили из файла:
css/style.css
Преимущество внешнего CSS-файла в том, что стили отделены от HTML-разметки и могут использоваться на нескольких страницах проекта.
4.7. Селекторы, свойства и значения CSS
CSS-правило состоит из селектора, свойства и значения.
Пример:
h1 {
  color: #222222;
  font-size: 32px;
}
Здесь:
h1 — селектор;
color и font-size — свойства;
#222222 и 32px — значения.
Основные виды селекторов:
Селектор
Пример
Что выбирает
По тегу
h1
все элементы h1
По классу
.product-card
элементы с классом product-card
По идентификатору
#catalog
элемент с id="catalog"
На данном этапе достаточно использовать селекторы по тегу и простые классы.
4.8. Наследование и каскадность
Некоторые CSS-свойства наследуются от родительского элемента к дочерним.
Например, если задать шрифт для body, он будет применён ко многим вложенным элементам:
body {
  font-family: Arial, sans-serif;
}
Каскадность означает, что если одно и то же свойство задано в нескольких местах, браузер выбирает итоговое значение с учётом приоритета селекторов и порядка правил.
На данном занятии не требуется глубоко разбирать специфичность CSS. Достаточно понимать:
правила ниже по файлу могут переопределять правила выше;
классы обычно удобнее для оформления повторяющихся блоков;
не следует злоупотреблять id и inline-стилями.
4.9. Блочная модель CSS
Каждый HTML-элемент на странице браузер воспринимает как прямоугольную область. Эта область называется блочной моделью.
Блочная модель состоит из четырёх частей:
Часть
Назначение
content
содержимое элемента: текст, изображение, вложенные элементы
padding
внутренний отступ между содержимым и рамкой
border
рамка элемента
margin
внешний отступ между элементом и соседними блоками
Пример:
.product-card {
  padding: 16px;
  border: 1px solid #dddddd;
  margin-bottom: 16px;
}
В этом примере:
padding: 16px; добавляет внутренний отступ внутри карточки;
border: 1px solid #dddddd; добавляет рамку;
margin-bottom: 16px; добавляет внешний отступ снизу между карточками.
4.10. Модели content-box и border-box
В CSS есть два основных способа расчёта размеров элемента.
content-box
Это стандартная модель браузера по умолчанию.
Если указать:
.card {
  width: 300px;
  padding: 20px;
  border: 2px solid #dddddd;
}
то итоговая ширина блока будет больше 300px, потому что padding и border добавляются к указанной ширине.
Итоговая ширина:
300px + 20px + 20px + 2px + 2px = 344px
border-box
В модели border-box указанная ширина уже включает content, padding и border.
.card {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 2px solid #dddddd;
}
В этом случае итоговая ширина блока останется 300px.
Поэтому в современных проектах часто в начале CSS-файла добавляют правило:
* {
  box-sizing: border-box;
}
Это делает расчёт размеров элементов более понятным и предсказуемым.
4.11. Минимальный сброс стилей
У браузеров есть встроенные стили по умолчанию. Например, у body есть внешний отступ, у списков есть маркеры и отступы, у заголовков — свои размеры и отступы.
Чтобы страница вела себя предсказуемо, в начале CSS-файла часто добавляют минимальный сброс стилей.
Для текущей практической работы достаточно такого варианта:
* {
  box-sizing: border-box;
}
body {
  margin: 0;
}
Что делает этот код:
* {
  box-sizing: border-box;
}
Правило применяется ко всем элементам страницы. Оно меняет расчёт ширины и высоты элементов так, чтобы padding и border входили в общий размер блока.
body {
  margin: 0;
}
Это правило убирает стандартный внешний отступ браузера у страницы. Если его не убрать, вокруг сайта может появиться нежелательный белый зазор.
На данном этапе не нужно подключать большой CSS-reset или normalize-файл. Достаточно минимального сброса, чтобы студенты понимали, какие стили они задают сами, а какие добавляет браузер.

4. Краткая теория
4.1. Для чего нужны формы
Форма — это основной способ получения данных от пользователя на сайте.
С помощью формы можно получить:
имя пользователя;
e-mail;
телефон;
выбранный товар или услугу;
дату;
комментарий;
согласие с условиями обработки данных.
В интернет-магазине или каталоге услуг форма может использоваться для оформления заявки, заказа обратного звонка или отправки вопроса.
4.2. Основные элементы формы
Элемент
Назначение
form
контейнер формы
label
подпись поля
input
поле ввода
select
выпадающий список
option
вариант выбора внутри select
textarea
многострочное поле
button
кнопка действия
Пример простой формы:
<form action="#" method="post">
  <label for="user-name">Имя</label>
  <input id="user-name" name="name" type="text" required>
  <button type="submit">Отправить</button>
</form>
Пояснение к коду:
form объединяет поля формы;
action="#" временно используется как заглушка, потому что backend пока не подключается;
method="post" показывает, что форма предназначена для отправки данных;
label задаёт подпись поля;
input создаёт поле ввода;
required делает поле обязательным;
button type="submit" отправляет форму.
4.3. Почему важны label, id и name
Каждое основное поле формы должно иметь подпись label.
Связь между подписью и полем выполняется через атрибуты for и id.
<label for="order-email">E-mail</label>
<input id="order-email" name="email" type="email" required>
В этом примере:
for="order-email" указывает, к какому полю относится подпись;
id="order-email" задаёт уникальный идентификатор поля;
name="email" задаёт имя поля, с которым данные будут отправляться.
Важно: placeholder не заменяет label. Подсказка внутри поля исчезает при вводе текста, а подпись должна оставаться понятной пользователю всегда.

Примеры:
<input type="text">
<input type="email">

Для телефона можно использовать дополнительный атрибут inputmode="tel". Он помогает мобильным устройствам показать более удобную клавиатуру для ввода номера.
4.5. Базовая HTML-валидация
Браузер умеет выполнять часть проверок формы без JavaScript.
Для этого используются специальные атрибуты:
Атрибут
Назначение
required
поле обязательно для заполнения
minlength
минимальная длина значения
maxlength
максимальная длина значения
pattern
проверка по регулярному выражению

Пример:
<input
  id="order-email"
  name="email"
  type="email"
  placeholder="example@mail.ru"
  required
>
Пояснение к коду:
type="email" включает проверку формата e-mail;
placeholder показывает пример ввода;
required запрещает отправить форму с пустым полем.
4.6. Что такое модальное окно
Модальное окно — это всплывающее окно, которое временно перекрывает основное содержимое страницы и требует действия пользователя.
В данной практической работе модальное окно используется для формы заявки.
Для реализации модального окна рекомендуется использовать HTML-элемент dialog.
Пример:
<dialog id="order-dialog">
  <h2>Оформление заявки</h2>
  <p>Здесь будет форма заявки.</p>
</dialog>
Преимущество dialog в том, что браузер уже умеет открывать его в модальном режиме с помощью метода showModal().
4.7. Минимальный JavaScript для модального окна
Для открытия и закрытия модального окна нужен JavaScript.
Пример:
const dialog = document.getElementById('order-dialog');
const openButton = document.getElementById('open-order-dialog');
const closeButton = document.getElementById('close-order-dialog');
openButton.addEventListener('click', () => {
  dialog.showModal();
});
closeButton.addEventListener('click', () => {
  dialog.close();
});
Пояснение к коду:
document.getElementById() получает элемент страницы по id;
addEventListener() назначает обработчик события;
click означает нажатие на кнопку;
showModal() открывает модальное окно;
close() закрывает модальное окно.
Подробная работа с DOM и событиями будет изучаться позже, в блоке JavaScript. На данном занятии JavaScript используется минимально, только для работы модального окна и базовой проверки формы.
4.8. Базовая JS-валидация
HTML-валидация проверяет поля автоматически. JavaScript можно использовать для дополнительной обработки: показать сообщение об успехе, сбросить форму или закрыть модальное окно.
Пример:
form.addEventListener('submit', (event) => {
  event.preventDefault();
  if (!form.checkValidity()) {
    form.reportValidity();
    return;
  }
  successMessage.textContent = 'Форма успешно отправлена!';
  form.reset();
  dialog.close();
});
Пояснение к коду:
событие submit возникает при отправке формы;
event.preventDefault() отменяет стандартную отправку формы;
form.checkValidity() проверяет ограничения HTML-валидации;
form.reportValidity() показывает стандартные подсказки браузера;
textContent изменяет текст сообщения на странице;
form.reset() очищает форму;
dialog.close() закрывает модальное окно.

Фрагмент head должен выглядеть так:

  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

Пояснение к коду:

defer откладывает выполнение скрипта до загрузки HTML-документа;
это позволяет обращаться к элементам страницы из JavaScript.

Этап 7. Реализация открытия и закрытия модального окна
Откройте файл js/main.js.
Добавьте код:
// Получаем модальное окно по id.
const orderDialog = document.getElementById('order-dialog');
// Получаем все кнопки заказа в карточках товаров.
const orderButtons = document.querySelectorAll('.product-card__button');
// Получаем кнопку закрытия модального окна.
const closeDialogButton = document.getElementById('close-order-dialog');
// Получаем скрытое поле, в которое будет записан выбранный товар.
const selectedProductInput = document.getElementById('selected-product');
// Перебираем все кнопки «Заказать».
orderButtons.forEach((button) => {
  button.addEventListener('click', () => {
    // Получаем название товара из data-атрибута.
    const productName = button.dataset.product;
    // Записываем название товара в скрытое поле формы.
    selectedProductInput.value = productName;
    // Открываем модальное окно.
    orderDialog.showModal();
  });
});
// Закрываем модальное окно по кнопке «Закрыть».
closeDialogButton.addEventListener('click', () => {
  orderDialog.close();
});
Пояснение к коду:
querySelectorAll() получает все кнопки заказа;
forEach() перебирает найденные кнопки;
addEventListener('click', ...) добавляет обработчик клика;
button.dataset.product получает значение атрибута data-product;
selectedProductInput.value записывает выбранный товар в скрытое поле;
orderDialog.showModal() открывает модальное окно;
orderDialog.close() закрывает модальное окно.
Этап 8. Добавление базовой обработки формы
В файл js/main.js ниже предыдущего кода добавьте:
// Получаем форму заявки.
const orderForm = document.getElementById('order-form');
// Получаем сообщение об успешной отправке.
const successMessage = document.getElementById('success-message');
// Обрабатываем отправку формы.
orderForm.addEventListener('submit', (event) => {
  // Отменяем стандартную отправку формы,
  // потому что backend пока не подключён.
  event.preventDefault();
  // Сбрасываем предыдущие признаки ошибок.
  const formElements = Array.from(orderForm.elements);
  formElements.forEach((element) => {
    if (element.willValidate) {
      element.removeAttribute('aria-invalid');
    }
  });
  // Проверяем встроенные HTML-ограничения формы.
  if (!orderForm.checkValidity()) {
    formElements.forEach((element) => {
      if (element.willValidate && !element.checkValidity()) {
        element.setAttribute('aria-invalid', 'true');
      }
    });
    // Показываем стандартные сообщения браузера.
    orderForm.reportValidity();
    return;
  }
  // Показываем сообщение об успешной отправке.
  successMessage.hidden = false;
  // Очищаем форму.
  orderForm.reset();
  // Закрываем модальное окно.
  orderDialog.close();
});
Пояснение к коду:
submit — событие отправки формы;
event.preventDefault() отменяет реальную отправку;
Array.from(orderForm.elements) превращает элементы формы в массив;
willValidate проверяет, участвует ли поле в валидации;
checkValidity() проверяет корректность формы;
reportValidity() показывает стандартные сообщения браузера;
aria-invalid="true" помечает ошибочные поля;
successMessage.hidden = false показывает сообщение об успехе;
reset() очищает поля формы.

Цель практического занятия — научиться организовывать CSS-файл учебного проекта, использовать CSS-переменные, задавать единые стили компонентов и оформлять состояния элементов интерфейса.

вынести основные цвета, отступы и скругления в переменные;

добавить состояния :hover, :focus, :focus-visible, :disabled;

проверить стили через DevTools;

4. Краткая теория
4.1. Что такое CSS-архитектура
CSS-архитектура — это способ организации стилей в проекте.
Даже в небольшом учебном проекте CSS-файл быстро разрастается. Если стили писать без структуры, возникают проблемы:
одинаковые цвета повторяются много раз;
отступы задаются случайными значениями;
сложно изменить общий вид проекта;
правила начинают конфликтовать друг с другом;
становится трудно понять, какие стили за что отвечают.
На данном занятии используется простая структура CSS-файла:
/* 1. Переменные */
:root {
  /* значения проекта */
}
/* 2. Базовые стили */
body {
  /* общие стили страницы */
}
/* 3. Общие элементы */
a,
button,
input {
  /* общие состояния */
}
/* 4. Компоненты страницы */
.site-header {
  /* шапка */
}
.product-card {
  /* карточка товара */
}
.order-dialog {
  /* модальное окно */
}
Такая структура помогает быстрее находить нужные правила и уменьшает количество случайных изменений.
4.2. Что такое :root
:root — это псевдокласс, который выбирает корневой элемент HTML-документа. Обычно это элемент html.
В CSS :root часто используется для хранения CSS-переменных.
Пример:
:root {
  --color-primary: #0057b8;
  --color-text: #222222;
  --space-md: 16px;
}
Пояснение к коду:
--color-primary — переменная для основного цвета проекта;
--color-text — переменная для цвета текста;
--space-md — переменная для среднего отступа.
CSS-переменные удобно использовать, потому что значение задаётся один раз, а затем применяется в разных частях проекта.
4.3. Как использовать CSS-переменные
Для использования CSS-переменной применяется функция var().
Пример:
.button {
  background-color: var(--color-primary);
  color: var(--color-white);
  padding: var(--space-sm) var(--space-md);
}
Пояснение к коду:
var(--color-primary) подставляет значение переменной --color-primary;
если цвет проекта изменится, достаточно поменять его в :root;
все элементы, использующие эту переменную, изменятся автоматически.
4.4. Зачем нужны переменные в учебном проекте
В учебном frontend-проекте переменные помогают:
использовать единые цвета;
не дублировать одни и те же значения;
быстрее менять оформление;
подготовить проект к масштабированию;
упростить последующий рефакторинг CSS.
Плохо:
.button {
  background-color: #0057b8;
}
.site-nav a {
  color: #0057b8;
}
.aside-info {
  border-left: 4px solid #0057b8;
}
Лучше:
:root {
  --color-primary: #0057b8;
}
.button {
  background-color: var(--color-primary);
}
.site-nav a {
  color: var(--color-primary);
}
.aside-info {
  border-left: 4px solid var(--color-primary);
}
Во втором варианте основной цвет проекта задаётся в одном месте.
4.5. Состояния элементов интерфейса
Пользователь взаимодействует с интерфейсом: наводит курсор, нажимает кнопки, переходит по ссылкам, заполняет формы с клавиатуры.
Для этих ситуаций в CSS используются состояния.
Состояние
Для чего используется
:hover
наведение курсора мыши
:active
момент нажатия
:focus
элемент получил фокус
:focus-visible
фокус должен быть явно показан пользователю
:disabled
элемент отключён
:visited
посещённая ссылка
Пример:
.button:hover {
  background-color: var(--color-primary-dark);
}
Этот код меняет цвет кнопки при наведении мыши.
4.6. Почему важен :focus-visible
Пользователь может работать с сайтом не только мышью, но и клавиатурой. Например, переходить между ссылками и полями формы с помощью клавиши Tab.
Если фокус не виден, пользователь не понимает, на каком элементе он находится.
Пример:
.button:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
}
Пояснение к коду:
outline добавляет видимую рамку фокуса;
outline-offset отодвигает рамку от элемента;
:focus-visible показывает фокус там, где он действительно нужен, например при навигации с клавиатуры.
4.7. Состояние :disabled
Состояние :disabled используется для элементов формы, которые временно недоступны.
Пример:
button:disabled {
  opacity: 0.6;
  cursor: not-allowed;
}
Пояснение к коду:
opacity: 0.6 визуально приглушает кнопку;
cursor: not-allowed показывает, что элемент недоступен;
пользователь понимает, что кнопку сейчас нельзя нажать.
4.8. Специфичность CSS на базовом уровне
Специфичность — это механизм, по которому браузер решает, какое CSS-правило применить, если несколько правил воздействуют на один и тот же элемент.
На данном этапе достаточно помнить:
селектор по тегу слабее, чем селектор по классу;
селектор по id сильнее, чем селектор по классу;
inline-стили обычно сложнее переопределять;
чем проще селектор, тем легче поддерживать CSS.
Плохо:
#main .content .section .product-card h3 {
  color: #222222;
}
Лучше:
.product-card__title {
  color: var(--color-text);
}
В этой практической работе не требуется полноценный переход на БЭМ. Рефакторинг CSS по БЭМ будет отдельной темой практического занятия №7.
4.9. Что пока не изучается подробно
На данном практическом занятии не требуется:
создавать новые HTML-страницы;
выполнять полноценный БЭМ-рефакторинг;
строить сетку Flex/Grid;
делать адаптивную вёрстку;
добавлять responsive images;
встраивать видео;
делать тёмную тему как обязательный функционал.
Эти темы будут рассмотрены в следующих практических занятиях.

7. Порядок выполнения работы
Этап 1. Создание ветки для практической работы
Создайте отдельную ветку:
git switch -c feature/css-architecture-states
Если команда git switch недоступна:
git checkout -b feature/css-architecture-states
Проверьте активную ветку:
git branch
Активной должна быть ветка:
feature/css-architecture-states
Этап 2. Подготовка структуры CSS-файла
Откройте файл css/style.css.
Разделите файл комментариями на смысловые блоки:
/* ===============================
   1. Переменные проекта
   =============================== */
/* ===============================
   2. Базовые стили
   =============================== */
/* ===============================
   3. Общие элементы интерфейса
   =============================== */
/* ===============================
   4. Компоненты страницы
   =============================== */
/* ===============================
   5. Форма и модальное окно
   =============================== */
Пояснение к коду:
комментарии помогают быстро ориентироваться в CSS-файле;
стили переменных лучше размещать в начале;
базовые правила должны идти раньше компонентов;
компоненты страницы лучше группировать по смыслу.
Этап 3. Добавление CSS-переменных
В начало файла добавьте блок :root:
/* ===============================
   1. Переменные проекта
   =============================== */
:root {
  /* Основные цвета проекта */
  --color-bg: #ffffff;
  --color-text: #222222;
  --color-muted: #666666;
  --color-primary: #0057b8;
  --color-primary-dark: #003f86;
  --color-border: #dddddd;
  --color-surface: #f7f7f7;
  --color-surface-accent: #eef5ff;
  --color-danger: #b00020;
  --color-success: #168a2f;
  --color-success-bg: #eefaf0;
  --color-white: #ffffff;
  /* Отступы */
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 24px;
  --space-xl: 32px;
  /* Скругления */
  --radius-sm: 6px;
  --radius-md: 8px;
  --radius-lg: 12px;
  /* Размеры */
  --container-width: 1100px;
}
Пояснение к коду:
переменные цветов начинаются с --color;
переменные отступов начинаются с --space;
переменные скруглений начинаются с --radius;
--container-width задаёт максимальную ширину контента;
такой подход помогает соблюдать единый стиль проекта.
Этап 4. Обновление базовых стилей
Найдите базовые стили страницы и замените значения на переменные.
Было:
body {
  margin: 0;
  font-family: Arial, sans-serif;
  line-height: 1.5;
  color: #222222;
  background-color: #ffffff;
}
Сделайте:
/* ===============================
   2. Базовые стили
   =============================== */
* {
  box-sizing: border-box;
}
body {
  margin: 0;
  font-family: Arial, sans-serif;
  line-height: 1.5;
  color: var(--color-text);
  background-color: var(--color-bg);
}
Пояснение к коду:
box-sizing: border-box сохраняется как минимальная настройка блочной модели;
color: var(--color-text) берёт цвет текста из переменной;
background-color: var(--color-bg) берёт цвет фона из переменной;
если потом изменить значения в :root, базовые стили обновятся автоматически.
Этап 5. Обновление общих отступов
Найдите стили для крупных областей страницы.
Было:
header,
main,
footer {
  padding: 20px;
}
Сделайте:
header,
main,
footer {
  padding: var(--space-lg);
}
Пояснение к коду:
вместо случайного значения 20px используется переменная --space-lg;
это помогает привести отступы проекта к единой системе.
Этап 6. Обновление шапки и подвала
Замените цвета шапки и подвала на переменные:
header {
  background-color: var(--color-surface);
}
footer {
  background-color: var(--color-surface);
}
Пояснение к коду:
--color-surface используется для нейтральных фоновых блоков;
если цвет фона нужно изменить, достаточно поменять переменную в :root.
Этап 7. Оформление ссылок и навигации
Добавьте раздел общих элементов интерфейса:
/* ===============================
   3. Общие элементы интерфейса
   =============================== */

  color: var(--color-primary);
}

  color: var(--color-primary-dark);
}

  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
}
Пояснение к коду:
a задаёт базовый цвет ссылок;
a:hover меняет цвет при наведении мыши;
a:focus-visible добавляет видимый фокус при навигации с клавиатуры.
Этап 8. Обновление кнопок
Найдите стили .button и замените значения на переменные:
.button {
  display: inline-block;
  padding: var(--space-sm) var(--space-md);
  color: var(--color-white);
  background-color: var(--color-primary);
  text-decoration: none;
  border: none;
  border-radius: var(--radius-sm);
  cursor: pointer;
}
.button:hover {
  background-color: var(--color-primary-dark);
}
.button:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
}
.button:disabled {
  opacity: 0.6;
  cursor: not-allowed;
}
Пояснение к коду:
padding теперь использует шкалу отступов;
background-color берётся из переменной;
border-radius берётся из переменной;
:hover показывает реакцию на наведение;
:focus-visible помогает пользователям клавиатуры;
:disabled показывает недоступное состояние кнопки.

  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
}
[aria-invalid="true"] {
  border-color: var(--color-danger);
}
Пояснение к коду:
:hover показывает реакцию поля при наведении;
:focus-visible показывает видимый фокус;
[aria-invalid="true"] выделяет поля с ошибками;
атрибут aria-invalid добавляется JavaScript-кодом из практического занятия №3.
