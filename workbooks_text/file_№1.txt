3. Краткая теория
3.1. Что такое 
Git
Git
 — это система контроля версий, которая позволяет отслеживать изменения в файлах проекта, сохранять историю разработки и возвращаться к предыдущим состояниям проекта.
Git
 особенно важен в веб-разработке, потому что позволяет:
фиксировать этапы разработки;
видеть, какие изменения были внесены;
работать с несколькими версиями проекта;
выполнять командную разработку через ветки и Pull 
Request
;
хранить проект в удалённом репозитории.
3.2. Что такое репозиторий
Репозиторий
 — это папка проекта, в которой 
Git
 отслеживает изменения файлов.
Репозиторий бывает:
локальный
 — находится на компьютере разработчика;
удалённый
 — находится на сервере, например на 
GitHub
.
Упрощённо:
Компьютер студента → 
GitHub
локальный проект     удалённый репозиторий
3.3. Что такое коммит
Коммит
 — это зафиксированное состояние проекта в определённый момент времени.
Коммит должен быть осмысленным. Не рекомендуется делать один большой коммит на всю работу. Лучше фиксировать изменения по этапам:
создана структура проекта;
добавлен файл 
index.html
;
подключён файл стилей;
оформлен 
README.md
;
добавлена ссылка на опубликованный сайт.
3.4. Что такое README.md
README.md
 — это файл с описанием проекта. Он должен объяснять, что находится в репозитории, как устроен проект и как его проверить.
Минимально в 
README.md
 должны быть:
название проекта;
краткое описание;
структура проекта;
используемые технологии;
ссылка на опубликованную версию сайта;
ФИО и группа студента.

3.6. Что такое ветка
Ветка
 — это отдельная линия разработки.
Основная ветка обычно называется:

Ветка

Для отдельной доработки создаётся отдельная ветка, например:
feature
/

Это означает: «ветка для доработки стартовой страницы».
3.7. Что такое Pull 
Request
Pull 
Request
 — это запрос на добавление изменений из одной ветки в другую.
В рамках данной практической работы Pull

 будет означать:
Добавить изменения из ветки 
feature
/
start-page
 в ветку 
main

Pull

 создаётся не в терминале, а в веб-интерфейсе

В терминале студент создаёт ветку, делает коммит и отправляет ветку в 
GitHub
. Затем в браузере на 
GitHub
 создаётся Pull 
Request
.
3.8. Что такое 
Merge
Merge
 — это слияние изменений.
После проверки Pull 
Request
 студент нажимает кнопку 
Merge
 
pull
 
request
. После этого изменения из ветки 
feature
/

 попадают в ветку 
main
.
3.9. Что такое 
GitHub
 
Pages
GitHub
 
Pages
 — это сервис 
GitHub
 для публикации статических сайтов.
Он позволяет открыть HTML/CSS-проект как обычный сайт в браузере.
Пример ссылки:
https://username.github.io/kr1-html-css-shop/
GitHub Pages — 
это
 
не
 Pull Request.

предложить изменения из одной ветки в другую
Merge
объединить изменения
GitHub
 
Pages
опубликовать сайт в интернете

Приложение А. Работа с 
GitHub
 на учебном компьютере и безопасное завершение занятия
А.1. Общая рекомендация
Если практическая работа выполняется на учебном компьютере, необходимо учитывать ограничения политики безопасности аудитории. У студента может не быть прав администратора, доступа к системным настройкам, диспетчеру учётных данных, установке программ или изменению глобальных параметров операционной системы.
Поэтому на учебных компьютерах рекомендуется использовать наиболее простой и безопасный сценарий:
Работать через веб-интерфейс 
GitHub
 и HTTPS-ссылки.
Не сохранять пароль, токен или данные входа в браузере.
После занятия выйти из аккаунта 
GitHub
.
Проверить, что в браузере не осталась открытая сессия.
При необходимости удалить локальную папку проекта, если это разрешено правилами аудитории.
SSH-ключи рекомендуется настраивать только на личном компьютере. На учебном компьютере SSH следует использовать только в том случае, если преподаватель отдельно разрешил этот вариант и объяснил порядок безопасного завершения работы.
А.2. Почему на учебном компьютере лучше использовать HTTPS
GitHub
 поддерживает несколько способов подключения удалённого репозитория. Для учебных занятий чаще всего достаточно HTTPS.
Пример HTTPS-ссылки:
https://github.com/username/repository-name.git
Пример SSH-ссылки:
git@github.com:username
/
repository-name.git
Для учебного компьютера предпочтительнее HTTPS, потому что он не требует создания SSH-ключа на машине, которой пользуются разные студенты.
А.3. Когда нужен SSH-ключ
SSH-ключ нужен для постоянной и удобной работы с 
GitHub
 без повторного ввода данных авторизации.
SSH удобно использовать:
на личном ноутбуке;
на домашнем компьютере;
на рабочем компьютере, который закреплён за конкретным пользователем;
при регулярной разработке и частом использовании 
git
 
push
 / 
git
 
pull
.
На учебном компьютере SSH-ключ использовать нежелательно, потому что приватный ключ может остаться на машине после занятия.
А.4. Как создать SSH-ключ на личном компьютере
Этот раздел предназначен для студентов, которые выполняют практические работы на личном компьютере.
Откройте терминал и выполните команду:
ssh-keygen -t ed25519 -C "your-email@example.com"
Вместо

, связанный с вашим аккаунтом

Если система предложит путь для сохранения, можно нажать

После создания ключа вы получите два файла:

Файл

Файл
